2. 사용자 권한

권한은 관리자(ADMIN) 와 일반 사용자(USER) 두 가지입니다. 가입 신청으로 만든 계정은 일반 사용자이며, 관리자가 승인할 때 관리자 권한을 줄 수 있습니다.

3. 로그인 / 로그아웃

  1. 웹 주소로 접속하면 로그인 화면이 나옵니다.
  2. 계정(ID) 과 비밀번호를 입력하고 [로그인] 을 누릅니다. Caps Lock 이 켜져 있으면 안내가 표시됩니다.
  3. 로그인 후 메인 홈으로 이동합니다. 로그인 전에 열려던 화면이 있으면 그 화면으로 이동합니다.
  4. 사용을 마치면 상단의 [로그아웃] 을 누릅니다. 30분 동안 사용하지 않으면 자동으로 로그아웃됩니다.

4. 사용자 가입 신청

  1. 로그인 화면 아래의 [사용자 가입 신청] 을 누릅니다.
  2. 항목을 입력합니다.
    항목규칙
    아이디 *영문으로 시작하는 4~30자 (영문, 숫자, . _ -). 이미 있는 아이디는 쓸 수 없습니다.
    이름 *50자 이내
    비밀번호 * / 확인 *8자 이상, 영문·숫자·특수문자를 모두 포함, 아이디를 포함할 수 없음
    이메일, 부서선택 입력 (승인 담당자가 신청자를 확인하는 데 사용)
    신청 사유 *200자 이내 (예: Murex 운영팀 서버 모니터링 조회)
  3. [가입 신청] 을 누르면 로그인 화면으로 돌아가며 “가입 신청이 접수되었습니다” 가 표시됩니다.
  4. 관리자가 사용자 관리 화면에서 승인하면 로그인할 수 있습니다.
입력 오류가 있으면 해당 칸 아래에 빨간 글씨로 표시됩니다. 보안을 위해 이때 비밀번호 칸은 비워지므로 다시 입력하세요.

5. 비밀번호 변경

두 곳에서 들어갈 수 있습니다.

  • 로그인 화면 아래 [비밀번호 변경] : 아이디, 현재 비밀번호, 새 비밀번호를 입력
  • 로그인 후 상단 [비밀번호 변경] : 아이디는 본인으로 고정
  1. 현재 비밀번호와 새 비밀번호(2번)를 입력하고 [비밀번호 변경] 을 누릅니다.
  2. 성공하면 로그아웃되고 로그인 화면에 “비밀번호가 변경되었습니다” 가 표시됩니다. 새 비밀번호로 다시 로그인하세요.
현재 비밀번호를 틀리면 로그인 실패와 똑같이 횟수가 쌓이며, 연속 5회 틀리면 계정이 잠깁니다. 새 비밀번호 규칙은 가입 신청과 같고, 현재 비밀번호와 같은 값은 쓸 수 없습니다. 승인 대기·반려·사용 중지·잠긴 계정은 변경할 수 없습니다.
처음 지급받은 관리자 계정은 첫 로그인 직후 반드시 비밀번호를 변경하세요.

6. 메인 홈

위에서부터 다음 순서로 표시됩니다.

  1. 장애 알람 배너 - 진행 중인 알람이 있을 때만 빨간(또는 주황) 상자로 표시. 없으면 초록색 “현재 진행 중인 장애 알람이 없습니다” → 7장
  2. 에이전트(krcasmrx11_client) 미등록 서버 - 등록이 안 됐거나 보고가 끊긴 서버 목록. 모두 정상이면 숨겨짐 → 8장
  3. 서버별 프로세스 카드 - 에이전트(krcasmrx11_client)가 연결된 서버만 카드(그래프 + 주요 프로세스)로 표시됩니다. ITC / DRC 묶음, 상단 [전체 / ITC / DRC] 로 필터
    • 머리글 : “연결 서버 M / N대 · 프로세스 실행 중 x / y”
    • 연결된 서버가 없는 묶음은 “🔌 이 구역에 에이전트가 연결된 서버가 없습니다” 와 [미등록 서버 목록 보기] 가 표시됩니다.
    • 미연결 서버는 위의 “에이전트 미등록 서버” 목록에서 확인하고, [등록 확인] 으로 연결되면 카드가 바로 나타납니다. 연결이 끊기면 다음 갱신(1분) 때 카드가 사라집니다.
    • 카드 위치 이동 : 카드 왼쪽 위 ⠿ 손잡이를 끌어서(마우스·터치) 같은 구역(ITC / DRC) 안에서 좌우·상하로 옮깁니다. 손잡이를 선택한 뒤 ← → 는 한 칸, ↑ ↓ 는 한 줄 이동합니다. 순서는 사용하는 브라우저에 저장되며 [카드 순서 초기화] 로 기본 순서로 되돌립니다.
  4. 카드 안 내용
    • 주요 프로세스 : 실행 상태·PID·CPU·MEM, 관리자는 기동/중지/삭제와 [+ 프로세스 찾아서 추가]
    • 그래프에 볼 프로세스 선택 : 주요 프로세스 목록 위 [📈 그래프 항목 선택 n / 6] 버튼을 누르면 선택 팝업이 열립니다.
      • 항목마다 실행 상태, PID, 최근 CPU 가 보이며 체크박스로 고릅니다. (최대 6개 - 6개를 고르면 나머지는 잠김, 색 = 그래프 선 색)
      • [이름으로 찾기] 검색, [CPU 상위 5개] 자동 선택, [모두 해제], [적용] 으로 반영 / [취소]·Esc 는 반영 안 함
      • 선택은 브라우저에 서버별로 저장되며, 카드 목록에는 선택된 항목 앞에 색 표시만 나옵니다. 처음에는 주요 프로세스 전체 / 서비스는 CPU 가 높은 실행 중 5개가 선택됩니다.
    • 주요 프로세스를 등록하지 않은 서버는 프로세스 관리 화면(service.list)에 등록된 서비스 목록만 보여 주며, 서비스도 골라서 서비스 CPU 그래프로 볼 수 있습니다. (서버의 krcasmrx11_client 1.3 이상이 서비스별 CPU 를 수집 - 이전 버전이면 상태 요약만 표시) [프로세스 관리에서 보기 / 제어] 로 이동합니다. 둘 다 없으면 “📋 주요 프로세스 미등록” 안내가 나옵니다.
    • 그래프 종류 : 선 / 막대 / 원 / 자원(서버 CPU·MEM), [확대] 로 크게 보기
    • 데이터 출처 표시 : 샘플 초기 데이터, 수집 에이전트 보고값
    • 1분마다 자동 갱신
    • 관리자는 카드 안에서 프로세스 기동/중지/삭제, [+ 프로세스 찾아서 추가] 가능

장애 대응 절차 (권장)

  1. 배너에서 알람 내용과 경과 시간을 확인합니다.
  2. [구성도] 로 서버 상태, 동기화 대상(DR 짝 서버) 상태를 확인합니다.
  3. 필요하면 [웹 콘솔] 로 접속하거나 담당 부서(인프라/네트워크)에 연락합니다.
  4. [확인 / 조치] 에 조치 내용을 기록합니다. 예) “14:20 전원 재기동 요청 (인프라 홍길동), 복구 확인 예정”
  5. 복구되면 다음 점검(1분 이내)에 알람이 자동 해소되고, 최근 해소 알람에 남습니다.
서버 상태 Down/Active 는 네트워크 구성도의 서버 정보 수정에서 바꾼 값입니다. 장애 복구 후에는 관리자가 상태를 Active(또는 Standby)로 되돌려야 서버 다운 알람이 해소됩니다.

10-2. 서버 로그

좌측 메뉴 서버자원모니터링 › 서버 로그. 웹 서버가 서버별로 정한 주기마다 서버의 krcasmrx11_client 에 로그를 요청하고, 에이전트가 보낸 로그 파일의 마지막 N줄을 보여 줍니다.

웹 서버
요청 주기 도래 / [지금 요청]→ 명령 확인 때 log 요청 → krcasmrx11_client
허용된 경로만 마지막 N줄→ 전송 → 서버 로그 화면
로그별 최근 20회 보관

화면 사용

  1. 대상 서버를 고릅니다. 에이전트 상태, 마지막 요청 / 마지막 수신 / 다음 요청 시각이 표시됩니다.
  2. 요청 주기 관리자 : 사용 안 함 / 1 / 5 / 10 / 30 / 60분. 바꾸면 에이전트가 다음에 확인할 때 바로 1회 요청하고, 이후 그 주기마다 요청합니다. (기본 5분)
  3. [지금 요청] 관리자 : 주기를 기다리지 않고 요청. 에이전트 데몬이 10초마다 웹을 확인하므로 10초 안에 들어옵니다. 화면은 15초마다 자동 갱신됩니다.
  4. 수집 대상 로그에서 로그를 누르면 오른쪽에 내용이 나옵니다.
    • 수집 시각 선택 (최근 20회), 검색(포함된 줄만), [오류] / [경고 이상] 걸러 보기, 줄바꿈, [내려받기](.txt)
    • 오류 줄은 빨간색, 경고 줄은 주황색으로 표시됩니다.
  5. 관리자 아래 로그 파일 추가 : 이름, 절대 경로, 가져올 줄 수(50~1000), 수집 여부. [자주 쓰는 경로] 버튼으로 바로 입력할 수 있습니다. 목록의 [수정] / [삭제] 로 관리합니다.

10-4. 하트비트 모니터링 (원격 서버 구동 유무)

좌측 메뉴 서버자원모니터링 › 하트비트 모니터링. 서버의 krcasmrx11_client 1.5 는 데몬과 따로 도는 하트비트 감시자(bin/scb_heartbeat.sh)가 정한 주기마다 웹으로 생존 신호와 데몬 상태를 보냅니다. 그래서 웹은 서버 다운과 데몬(scb_client)만 문제인 경우를 구분합니다.

상태뜻화면 처리
수신 중하트비트를 받고 있고 데몬도 정상-
서버 다운하트비트를 3회 연속(주기 x 3 + 2초) 못 받음 - 서버 전원·네트워크 문제그 서버의 모니터링 대상 프로세스·서비스를 즉시 종료, 서버는 Down 으로 표시하고 알람
데몬 문제하트비트는 오는데 데몬만 멈춤 / 비정상 종료 / 응답 없음서버는 Down 으로 표시하지 않음. 프로세스는 정보가 없어 종료로 표시하고 “데몬 중단” 알람 + [데몬 재시작] 버튼 관리자
데몬 종료이전 클라이언트(1.4 이하)가 종료를 보고함서버는 Down 아님, 서버에서 bin/scb_client.sh start
없음토큰 미발급, 데몬 미실행, crontab 방식 이전 클라이언트-
  • 서버 카드 : 상태, 마지막 수신 시각과 경과 시간(매초 갱신), 연속 미수신 ●●● (n / 3회), 다운 기준 대비 경과 막대, 주기·기준, 데몬 PID, 에이전트 상태·버전. 화면은 2초마다 갱신되고 다른 화면(메인 홈, 구성도, 서버 전체 목록, 프로세스 관리, 알람)도 3초 안에 저절로 바뀝니다.
  • [데몬 재시작] : 데몬 문제 카드, 네트워크 구성도 서버 상세, 메인 홈 “데몬 중단” 알람, 에이전트 관리 화면에 나옵니다. 누르면 다음 하트비트 응답으로 서버의 감시자가 bin/scb_client.sh start 를 실행합니다. (서버 작업 불필요, 클라이언트 1.5 이상)
  • 일부러 멈춘 경우(웹 [종료], 서버 scb_client.sh stop)는 알람 없이 화면 안내와 [데몬 재시작] 만 나옵니다.
  • 서버 복구 자동 감지 (클라이언트 1.6~) : 다운됐던 서버가 되살아나 하트비트가 다시 오면 “복구” 로 기록하고(부팅 시각이 바뀌면 재부팅으로 표시)
    • 데몬이 안 떠 있으면 자동 재시작 (관리자가 일부러 멈춘 데몬은 제외)
    • 데몬이 떠 있으면 바로 수집·보고 요청 → 수집 주기를 기다리지 않고 서버 자원·프로세스 정보가 곧바로 다시 표시
  • 부팅 자동 시작 : 서버가 재부팅된 뒤 데몬·감시자가 자동으로 떠야 위 복구가 됩니다. 카드에 “미설치” 로 나오면 서버에서 root 로 bin/scb_client.sh install-boot 를 한 번 실행하세요.
  • 하트비트 이벤트 이력 : 수신 시작 / 서버 다운(끊긴 시간) / 복구 / 데몬 중단 / 데몬 다시 실행 / 재시작 요청 / 데몬 종료 / 주기 변경. (웹 서버 logs/heartbeat.log 에도 기록)
  • 주기 변경 : 네트워크 구성도 › 서버 › 서버 에이전트 › 하트비트 주기 관리자
클라이언트 1.4 는 하트비트가 데몬과 함께 멈추므로 데몬이 죽으면 서버 다운으로 보입니다. 1.3 이하(하트비트 셸 없음)는 데몬의 웹 확인(10초)을 하트비트로 쓰며 기준은 45초입니다(이전 방식 표시). 데몬 문제 구분과 웹 재시작을 쓰려면 1.5 로 교체하세요. (14장)

10-5. 데몬 중단 프로세스 현황

좌측 메뉴 서버자원모니터링 › 데몬 중단 프로세스 현황. 데몬(scb_client)이 죽거나 멈춰도 서버의 프로세스는 살아 있을 수 있습니다. 이때 하트비트 감시자(클라이언트 1.7 이상)가 30초마다 서버 자원과 프로세스·서비스 상태를 대신 수집해 이 화면에 보여 줍니다.

  • 서버별 카드 : 데몬 상태(비정상 종료 / 정지), 수집 시각, 데몬 중단 후 처음 수집 시각·횟수, CPU / MEM / DISK, 주요 프로세스(실행 중·종료, PID, CPU, MEM), 서비스(service.list) 상태. 5초마다 갱신
  • 다른 화면(메인 홈, 네트워크 구성도, 프로세스 관리)은 데몬 정보 기준이라 데몬이 멈추면 프로세스를 종료로 표시합니다. 실제로 살아 있는지는 이 화면에서 확인하세요.
  • 데몬이 다시 시작되면([데몬 재시작], 서버에서 bin/scb_client.sh start, 서버 복구 자동 재시작) 이 화면의 정보는 자동으로 삭제되고 다른 화면이 정상 정보로 돌아옵니다.
  • 서버 실행 중 프로세스 (클라이언트 1.8~) : 서버에서 실제로 돌고 있는 전체 프로세스(ps - PID, PPID, 사용자, CPU, MEM, 경과 시간, 명령)를 CPU 높은 순으로 최대 300건 보여 줍니다. 하트비트 감시자와 그 수집 작업은 목록에서 제외됩니다. 검색(PID·사용자·명령), 정렬(CPU / MEM / PID / 사용자 / 주요 프로세스 먼저), 30건 넘으면 [전체 보기]. 등록된 주요 프로세스·서비스와 맞는 줄은 파란색으로 강조됩니다.
  • 하트비트 모니터링 카드와 구성도의 데몬 알림에 “데몬 중단 중 프로세스 현황 보기” 링크가 있습니다.
  • 새 정보가 90초 넘게 없으면(감시자 수집 지연) 또는 하트비트까지 끊기면(서버 다운) 카드가 빨간 테두리로 바뀌고 “마지막으로 받은 정보” 임을 알려 줍니다.
  • 정보가 아직 없는 서버도 표시합니다 (하트비트는 오는데 데몬이 멈춘 서버) : 정보 수집 중 은 곧 첫 정보가 오는 경우, 정보 없음 은 원인과 조치를 함께 보여 줍니다.

11. 프로세스 관리

서버의 service.list 에 등록된 서비스의 상태와 PID 를 보여 주고, 관리자는 제어 명령을 요청할 수 있습니다.

  1. 상단에서 서버를 선택합니다. 에이전트 상태(정상 / 보고 대기 / 보고 끊김)가 함께 표시됩니다.
  2. 서비스 목록에서 상태(RUNNING STOPPED UNKNOWN)와 PID, 확인 시각을 봅니다.
  3. 관리자 [+ 프로세스 추가] 로 선택한 서버에 서비스(service.list 한 줄 : GROUP, LEVEL, 서비스명, 계정, 제어 스크립트, ARG, 지원 명령)를 추가하고, 목록의 [수정] / [삭제] 로 고칩니다. 값은 service.list 가져오기와 같은 규칙으로 검사하며, 삭제하면 뒤의 순번(NO)이 당겨집니다.
  4. [service.list 문서 만들기] : 현재 목록을 service.list 형식 문서로 만들어 [복사] / [내려받기] 합니다. (SCRIPT 는 SCB_SCRIPT_HOME 아래면 상대 경로) 웹에서 목록을 바꾸면 “서버 반영 필요” 안내가 나오며, 이 문서를 서버의 krcasmrx11_agent/etc/service.list 로 저장해야 scb_main.sh 제어에 적용됩니다.
  5. [제어 이력] (서버 전체 100건) / 목록 각 줄의 [이력] (그 서비스 + 그 서비스가 속한 그룹·Level·전체 명령 50건) 팝업 : 상태·명령으로 걸러 보기, [보기] 로 실행 결과 확인
  6. (관리자) 서비스별 버튼 또는 일괄 제어(전체 / 그룹 N / Level N)로 start, stop, restart, status, kill, clean 을 요청합니다. service.list 에 정의되지 않은 명령은 요청할 수 없습니다.
  7. 요청은 에이전트가 가져가 실행합니다. 아래 제어 명령 이력에서 상태(요청 → 전달 → 완료/실패)와 실행 결과(출력, 종료코드)를 확인합니다.
서버 정보를 받아오지 못하면 서버는 “Down”, 프로세스는 “종료” 로 표시 (모든 화면 공통 - 메인 홈, 네트워크 구성도, 서버 전체 목록, 프로세스 관리, 웹 콘솔)
  • 서버 : 에이전트가 정상 보고 중이 아니면 등록 상태(Active / Standby)와 관계없이 Down 으로 표시하고 사유를 함께 보여 줍니다. 예) 서버 전체 목록 DISCONNECTED (Down) · 서버 정보 수신 안 됨 · 보고 끊김. 등록된 상태 자체는 바뀌지 않으며, [서버 정보 수정] 화면에는 등록 상태가 그대로 나옵니다.
  • 서버 단위 : 에이전트가 정상 보고 중이 아니면(미설치 · 보고 대기 · 보고 끊김 · 수집 중지 · 데몬 종료) 그 서버의 주요 프로세스와 service.list 서비스를 모두 종료로 바꿉니다. (60초마다 점검)
  • 프로세스 단위 : 보고는 들어왔지만 특정 프로세스·서비스 정보가 빠져 있으면 그것만 종료로 바꿉니다.
  • 실행 중 → 종료로 바뀐 내용은 웹 서버의 logs/process-status.log 에 기록됩니다. (서버·프로세스명·이전 PID·사유)
  • 다음 정상 보고가 들어오면 보고된 실제 상태로 돌아옵니다.
에이전트가 10분 안에 가져가지 않은 요청, 30분 안에 결과가 오지 않은 요청은 “만료” 처리됩니다. (관리자) [service.list 가져오기] 로 서버의 service.list 내용을 다시 등록할 수 있습니다.

  5. (서버) 업그레이드 : bin/scb_client.sh stop → 같은 위치에 새 tar 풀기 → bin/scb_client.sh start (etc/client.env 는 그대로 유지). 1.5 부터 하트비트 감시자(bin/scb_heartbeat.sh)가 데몬과 따로 실행되며 bin/scb_client.sh status 에 상태가 나옵니다. stop 은 데몬만, stopall 은 데몬과 감시자를 모두 멈춥니다. 부팅 스크립트(etc/scb_client.init)도 새로 복사하세요.
  6. (서버) 부팅 시 자동 시작 (한 번) : cp etc/scb_client.init /etc/init.d/scb_client, chmod 744 /etc/init.d/scb_client, ln -s /etc/init.d/scb_client /etc/rc3.d/S99scb_client, ln -s /etc/init.d/scb_client /etc/rc0.d/K01scb_client
  7. (웹) 메인 홈 “에이전트 미등록 서버” 에서 해당 서버의 [등록 확인] → “✔ 등록 확인됨”
에이전트는 웹 서버로 나가는 연결만 사용하며 서버에 포트를 열지 않습니다. 토큰은 서버별로 다르고 DB 에는 해시값만 저장됩니다.

15. 자주 묻는 질문 / 문제 해결

수정·삭제 버튼이 보이지 않습니다.

일반 사용자 계정입니다. 관리자에게 권한 변경을 요청하세요. (사용자 관리 → 관리자로)

“권한이 없습니다” 또는 관리자 전용 화면 안내가 뜹니다.

관리자 기능을 일반 사용자로 실행했거나 로그인 세션이 만료된 경우입니다. 새로고침 후 다시 로그인하세요.

서버를 복구했는데 빨간 알람이 계속 남아 있습니다.

구성도에서 서버 상태가 아직 Down 인지 확인하고 Active/Standby 로 수정하세요. 수정 즉시 점검되어 알람이 해소됩니다.

“에이전트 보고 끊김” 이 반복됩니다.

서버에서 bin/scb_client.sh ping / status 결과, log/scb_client.log, 웹 서버 방화벽을 확인하세요. 토큰을 재발급했다면 client.env 도 새 토큰으로 바꿔야 합니다.

서버에서 웹 서버 연결 실패 (http://localhost:…) 가 나옵니다.

서버에서 localhost 는 그 서버 자신입니다. etc/client.env 의 SCB_WEB_URL 을 서버에서 접속 가능한 웹 서버 PC 의 IP 로 바꾸세요. (예: http://10.x.x.x:8080/server-monitoring-web) 토큰은 그대로 두면 됩니다.

확인 순서 : 서버에서 ping 웹서버IP → bin/scb_client.sh ping. 응답이 없으면 웹 서버 PC 방화벽에서 해당 포트(8080 / 8081) 허용, 서버 → 웹 서버 네트워크 경로를 확인하세요. 토큰 발급 화면은 화면을 localhost 로 열었으면 이 PC 의 IP 로 바꿔 보여 주며, 항상 같은 주소를 쓰려면 운영 담당자가 app.agent.public-url 을 지정합니다.

그래프에 “샘플” 이라고 나옵니다.

아직 에이전트 보고가 없어 초기 샘플 데이터를 보여 주는 것입니다. 에이전트가 등록되면 “수집” 으로 바뀝니다.

알림음이 나지 않습니다.

[알림음] 체크 여부를 확인하세요. 일부 브라우저는 화면을 한 번 클릭하기 전에는 소리를 막습니다.

웹 콘솔 창이 열리지 않습니다.

브라우저 팝업 차단을 해제하세요. 접속 허용 목록에 없는 서버는 접속되지 않습니다.

16-2. DB 구성 (MySQL · MariaDB · H2 · Sybase · Oracle) 운영

모니터링 데이터(서버, 프로세스, 이력, 알람, 사용자)는 주 DB 하나에 저장합니다. 주 DB 는 실행 패키지 conf/scb_web.env 의 SCB_DB 로 고릅니다.

SCB_DB동작
auto (기본)MySQL 에 먼저 연결 (3초) → 안 되면 MariaDB 임베디드 (웹이 직접 시작) → MariaDB 프로그램이 없으면 (Solaris 10 SPARC) H2 파일 DB
mysqlMySQL 만 (연결 안 되면 시작 실패)
mariadbMariaDB 만 - 기본은 임베디드 (127.0.0.1:13307, 데이터 data/mariadb), 외부 MariaDB 는 SCB_MARIADB_EMBEDDED=false + SCB_MARIADB_URL
h2H2 파일 DB 만 (자바만으로 동작, Windows · Solaris 10 SPARC 모두, 데이터 data/h2)
  • 임베디드 MariaDB : Windows 실행 패키지에 MariaDB 10.11 LTS 가 들어 있습니다 (mariadb/windows-x64). 처음 쓸 때 데이터 폴더·스키마·기본 데이터를 자동으로 만들고, 웹을 멈추면 함께 종료됩니다. root 비밀번호는 무작위로 정해 data/mariadb.scb-embedded.properties 에 저장됩니다 (외부에 주지 마세요).
  • Solaris 10 SPARC : MariaDB 는 이 플랫폼용 실행 파일을 배포하지 않아 H2 를 씁니다. MySQL 이 연결되면 MySQL 을 그대로 씁니다.
  • 데이터 옮기기 : 웹을 멈춘 뒤 bin\scb_web.bat migrate-db mysql:mariadb (Solaris : bin/scb_web.sh migrate-db mysql:h2). 원본의 모든 테이블을 대상에 덮어쓰고 테이블별 건수를 비교합니다. 반대 방향(mariadb:mysql 등)도 됩니다.
  • 보조 연결 : Sybase (SPRING_PROFILES=default,sybase), Oracle (default,oracle + SCB_ORACLE_URL / SCB_ORACLE_USER / SCB_ORACLE_PASSWORD). 개발 코드에서는 MysqlJdbc / MariaDbJdbc / H2Jdbc / SybaseJdbc / OracleJdbc 를 각각 주입받아 씁니다.
  • 상태 확인 : GET /api/db/status - 지금 주 DB 와 선택 이유, DB 별 연결 상태·버전.
데이터를 옮기면 대상 DB 의 내용은 원본으로 바뀝니다. 운영 중인 웹은 먼저 멈추세요 (scb_web.bat 이 실행 중이면 거부합니다).
