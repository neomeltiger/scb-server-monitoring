사용 안내

판정 기준
  • 수신 중 하트비트를 받고 있고 데몬도 정상
  • 서버 다운 하트비트를 3회 연속(주기 x 3 + 2초) 못 받음 → 그 서버의 모니터링 대상 프로세스·서비스를 즉시 종료, 서버를 Down 으로 표시하고 알람. 카드의 연속 미수신 ●●● 로 진행 상황 확인
  • 데몬 문제 하트비트는 오는데 데몬(scb_client)만 멈춤·비정상 종료·응답 없음 → 서버는 Down 이 아님. 프로세스는 정보가 없어 종료로 표시하고 "데몬 중단" 알람과 함께 [데몬 재시작] 버튼 표시 (관리자, 클라이언트 1.5 이상)
  • 데몬 종료 이전 클라이언트(1.4 이하)가 종료를 보고함 - 서버에서 bin/scb_client.sh start
  • 없음 토큰 미발급, 아직 데몬이 시작되지 않음, 또는 cron 방식 이전 클라이언트
주기 설정 / 서버
  • 하트비트 주기 : 네트워크 구성도 → 서버 클릭 → 서버 에이전트 → 하트비트 주기 (관리자, 3 / 5 / 10 / 15 / 30 / 60초). 다음 하트비트부터 바로 적용
  • 하트비트 감시자 : 클라이언트 1.5 의 bin/scb_heartbeat.sh - bin/scb_client.sh start 가 데몬과 따로 실행해 데몬이 죽어도 계속 하트비트와 데몬 상태를 보냅니다. [데몬 재시작] 요청도 이 감시자가 받아 실행합니다. (모두 끄기 : bin/scb_client.sh stopall)
  • 서버 복구 자동 감지 (1.6~) : 서버가 되살아나 하트비트가 다시 오면 복구 로 기록하고(부팅 시각이 바뀌면 재부팅으로 표시), 데몬이 안 떠 있으면 자동 재시작, 떠 있으면 바로 수집·보고를 요청해 서버 자원·프로세스 정보를 곧바로 다시 보여 줍니다. (관리자가 일부러 멈춘 데몬은 자동 재시작하지 않음)
  • 재부팅 후에도 자동으로 되살아나려면 서버에 부팅 자동 시작이 설치되어 있어야 합니다. 카드의 “부팅 자동 시작 : 미설치” 서버는 root 로 bin/scb_client.sh install-boot
  • 1.3 이하 클라이언트는 데몬의 웹 확인(10초)을 하트비트로 쓰며 끊김 기준은 45초입니다. (이전 방식 표시)
  • 이벤트는 웹 서버 logs/heartbeat.log 에도 남습니다.
